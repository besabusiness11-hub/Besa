# CLAUDE.md

BESA agency site (besaweb.com, "BESA 2.0"): Italian single-page landing selling landing pages to businesses that run Meta (FB/IG) ads, plus legal pages. Standalone repo since 2026-11-09 (split out of the `besa-platform` monorepo with full history; GitHub `besabusiness11-hub/Besa`, branch `main`). Read `DESIGN.md` and `PRODUCT.md` (Impeccable brand register) before UI edits; `DEPLOY.md` for Coolify.

## Hard rules
- No cookies, no third-party embeds, no CDN fonts. Analytics = self-hosted Umami only.
- Node 24 (`fnm use 24`), pnpm 11. Build-script approvals and the `@astrojs/language-server` pin live in `pnpm-workspace.yaml` (2.17.x crashes `astro check` with `this.bridge.deleteEnv is not a function`). `esbuild` is a direct devDependency because `vite.build.cssMinify: "esbuild"` needs it.
- Docker: `docker build -t besa-agency-site .` from the repo root (Coolify: Base Directory `/`, Dockerfile `/Dockerfile`, port 4321, healthcheck `/healthz`).
- Always use absolute paths in Bash. Commits: conventional (`feat(agency-site): …`), Italian copy in "tu" register.

## Details
Separate product from the gym pipeline: Italian single-page landing selling landing pages to businesses that run Meta (FB/IG) ads, plus legal pages. Read `DESIGN.md` and `PRODUCT.md` (Impeccable brand register) before UI edits; `DEPLOY.md` for Coolify.
- **Switches live in `src/lib/features.ts`** (2026-11-02, spec `docs/specs/agency-site-fase-validazione.md`): `OFFER_MODE` ("validation" | "launch" | "full") plus `FEATURES` (`leadForm`, `onlinePayment`, `whatsappButton`), each off switch with `whyOff` + `reEnable` checklist (tested). No env override: change the file and redeploy. `pnpm features` prints what is off and why. Current: validation, everything off. `offer.ts` keeps `PRICING` and derives `FULL`/`LAUNCH`/`VALIDATION`; "launch" = old prelaunch (one landing at €390), "full" = three plans + quote slider. `copy.ts` exports `buildCopy(mode, { leadForm })` (tests build every mode) and `copy` = current switches. In "validation" no amounts/"gratis" anywhere (`copy.test.ts` scans with an explicit allowlist), `offer`/`form.payment` are absent, the offer section is `OfferValidation.astro`, `/termini` is a noindex stub out of sitemap and footer. `/termini` (launch/full) holds cancellation, pause, code-buyout prices (never in marketing copy). WhatsApp shows only with `whatsappButton.enabled` AND `PUBLIC_WHATSAPP_NUMBER`.
- Commands: `pnpm dev` (astro dev; Astro 7 runs it as a daemon: `pnpm exec astro dev stop` if CSS looks stale) · `pnpm check` · `pnpm test` (vitest; single file: `pnpm exec vitest run src/lib/lead.test.ts`) · `pnpm build` (`prebuild` renders `public/og/home.png` via Playwright; without Chromium it keeps the committed PNG) · `HOST=127.0.0.1 PORT=4321 node server.mjs` to serve the production build (without `HOST` it binds IPv6 only).
- Lead capture with `leadForm` OFF (now): every `LinkCatcher` (hero, step 1, calculator, offer) opens the visitor's mail app with a draft to info@besaweb.com (`lib/mail-draft.ts` pure builder, `lib/mail-state.ts` client state: last link, calculator numbers, plan). `MailCard.astro` is the copy-paste popup (A/Oggetto/Messaggio + Copia), `ContactMail.astro` replaces the form in `#contatto`. `/api/lead` returns 404, CSP drops Turnstile (`server.mjs` imports `features.ts` via Node type stripping). Umami events `mail_open{where}`, `mail_card_open`, `mail_copy{field}`. DOM check: `node scripts/check-mail-flow.mjs <url>`. Never put `data-tpl` on anything outside the calculator: `Problem.astro` rewrites the text of every `[data-tpl]`.
- Lead capture with `leadForm` ON: `LinkCatcher` drops the link into the contact form. The form (`ContactForm.astro`) has 3 required answers (link, name, contact) plus optional goal, plan, calculator numbers and a "more context" disclosure; `DemoMonitor` sketches the trial page live, `ReceiptPrinter` prints the summary on send (1 business day ETA, text download, confetti via lazy `canvas-confetti`). Every optional field must exist in `leadSchema` + `buildEmail` + tests + the privacy policy list, or it is silently dropped. Privacy/cookie pages switch their Brevo/Turnstile paragraphs on the same flag. Its CSS still ships when off (Astro collects CSS from imports), its JS does not.
- `server.mjs` compression decides at `writeHead` time: SSR responses commit headers there; deciding later broke every browser form submission.
- Architecture: Astro + Tailwind 4 + `@astrojs/node` standalone. Pages are prerendered; only `POST /api/lead` (`src/pages/api/lead.ts` + `src/lib/lead.ts`) runs server-side (zod, honeypot `website`, Turnstile, nodemailer SMTP, in-memory rate limit). `server.mjs` is the production entry (security headers, compression, cache headers, `X-Robots-Tag`); `src/middleware.ts` adds CSP.
- All Italian copy lives in `src/lib/copy.ts`; `{em}…{/em}` marks emphasis. `copy.test.ts` fails on any `[TODO]` left in copy. **Never invent prices, testimonials, stats, legal/company data**: leave the field empty or omitted and ask. Only team = Leo and Ben (Benito, shown as "Ben" everywhere on the site since 2026-11-03); their portraits are SVG "besamoji" in sticker style (`TeamAvatar.astro`), never photos of faces. `apps/agency-site/STATO.md` is the owner-facing summary of what is on/off: update it when a switch changes.
- Design tokens: primitives in `@theme`, components use only semantic tokens (`@theme inline` in `src/styles/global.css`). Type classes are `.t-h2/.t-h3` (Tailwind `h-2/h-3` collide). Never name a component class after a Tailwind utility (`ring`, `h-2`, …): Tailwind 4 scans the source and applies the utility too (`.ring` drew a 1px box-shadow square on the Lighthouse gauges and the dock ring). Motion is CSS-only (`animation-timeline: view()`), must respect `prefers-reduced-motion`. Never put `overflow-hidden` on an ancestor of a `view()` animation: it makes a scroll container and freezes the timeline (use `overflow-clip`; this silently broke all of "Come funziona" until 2026-11-03). Word-by-word scroll headlines: `LitHeadline.astro` (spreads rest props so the caller's scoped classes apply). `vite.build.cssMinify: "esbuild"` is required: Lightning CSS breaks `animation-timeline`.
- Copy rules: no em dashes, informal "tu", smart punctuation, no buzzwords. Delivery promise confirmed by the owner (2026-11-03): draft in 48 hours, first reply within 1 business day; WhatsApp only if the visitor leaves a number in the email. No CTA in the sticky header (removed 2026-11-03: logo only). "Ottieni la bozza" is the one CTA label everywhere (link fields, footer, dock pill `nav.dockCta`). Page and card (`[popover]`) scrollbars are hidden in `global.css`; `Base.astro` resets every popover to its top on open. Prices, payment links (`offer.plans[].checkout`), bios, case studies and legal data are still `[TODO]`/empty: never fill them by guessing.
- Env: `PUBLIC_SITE_URL` and `PUBLIC_NOINDEX=true` (staging noindex) are build-time; set `TRUSTED_PROXY=cloudflare` in prod or all visitors share one rate-limit bucket. SMTP/Turnstile vars in `.env.example`.
- JSON-LD FAQPage includes only FAQ items without a `[TODO]`; text must match the visible answer exactly (tested in `jsonld.test.ts`).
- Old Vite site `../Besa/` stays untouched until the user approves the new site.
